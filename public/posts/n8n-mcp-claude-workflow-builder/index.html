왜 이 서버가 워크플로 작업에 닿는가

포스트의 첫 문장은 "n8n 자동화, 이제 클로드한테 말로 시키면 끝이야..?"입니다. 이어지는 문장은 n8n 워크플로를 클로드가 대신 짜 주는 도구가 있고, 깃허브 별이 2.3만 개이며, 이름은 n8n-mcp이고, 스킬보다 MCP라는 것입니다. 붙는 클라이언트로 클로드 데스크톱, 클로드 코드, 윈드서프, 커서를 적고, 마지막에는 n8n이 따로 돌아가야 하며 만든 흐름은 본인이 확인해야 한다고 적습니다.

그 저장소는 있습니다. GitHub 설명 문장은 "A MCP for Claude Desktop / Claude Code / Windsurf / Cursor to build n8n workflows for you"입니다. 2026-11-04 API의 별은 23,199, 포크는 3,681, 라이선스 SPDX는 MIT, 기본 브랜치는 main, 아카이브 상태는 아닙니다. npm latest는 2.101.0이고, 같은 태그 릴리스 시각은 2026-11-03 19:25:46Z입니다. 릴리스 노트는 n8n을 2.46.x로 올렸다고 적고, README 배지는 n8n 2.46.4를 가리킵니다. 배지와 릴리스 노트의 대응은 그 문서에 있고, 이 글은 node_modules 안의 n8n 패키지 버전을 다시 풀지 않았습니다.

개발자에게 닿는 지점은 "말로 시키면 워크플로 JSON이 생긴다"의 경로입니다. n8n-mcp는 모델이 노드 스키마를 조회하고, 설정을 검증하고, API 키가 있을 때 n8n의 공개 REST API로 워크플로를 만듭니다. 모델을 대신하는 실행 엔진은 이 프로세스 안에 없습니다. docs/SELF_HOSTING.md는 Docker 이미지에 n8n 의존성이 없다고 적습니다. 이미지가 주장하는 "~280MB", "일반 n8n 이미지보다 82% 작다"는 그 문서의 문장이고, 이 글은 이미지를 pull해 크기를 재지 않았습니다.

MCP가 이 서버에서 하는 일

MCP 명세 2026-07-28에서 서버가 모델에 넘기는 기능은 tools, resources, prompts입니다. tools는 모델이 고르고 호출하는 함수입니다. 명세는 도구 호출을 거절할 수 있는 사람이 루프 안에 있어야 한다고 적고, 호스트가 어떤 도구가 모델에 보이는지, 언제 호출되는지를 보여 주기를 권합니다. 프로토콜이 호스트의 확인 창을 대신 만들어 주지는 않습니다.

stdio에서는 클라이언트가 서버를 자식 프로세스로 띄웁니다. 서버는 stdin에서 줄 단위 JSON-RPC를 읽고, stdout에는 MCP 메시지만 씁니다. 로그는 stderr입니다. n8n-mcp의 Claude Desktop 설정이 MCP_MODE=stdio를 필수로 적는 이유가 이 규칙입니다. SELF_HOSTING.md는 이 변수가 없으면 디버그 로그가 stdout에 섞여 "Unexpected token..." 같은 JSON 파싱 오류가 난다고 적습니다. src/mcp/server.ts는 MCP_MODE가 설정돼 있고 그 값이 http가 아니면 stdout 가드를 설치합니다.

로컬 npx/docker run -i 경로는 이 stdio입니다. 원격으로 띄울 때는 명세의 다른 표준 전송인 Streamable HTTP가 있고, 저장소는 docs/HTTP_DEPLOYMENT.md와 Railway 버튼을 따로 둡니다. 이 글은 HTTP 배포를 띄워 보지 않았습니다.

n8n에 대한 호출은 MCP 전송과 별개입니다. src/config/n8n-api.ts의 getN8nApiConfig()는 N8N_API_URL과 N8N_API_KEY가 둘 다 있을 때만 설정을 반환합니다. 하나라도 없으면 관리 도구는 붙지 않습니다. src/services/n8n-api-client.ts는 그 URL의 해시를 지우고, 끝에 /api/v1이 없으면 붙인 뒤, 헤더 X-N8N-API-KEY로 n8n 공개 REST API를 호출합니다. 타임아웃 기본값은 30,000ms, 재시도 기본값은 3입니다. 인증된 클라이언트는 maxRedirects: 0입니다. N8N_CF_CLIENT_ID와 N8N_CF_CLIENT_SECRET이 있으면 Cloudflare Access 헤더로 나갑니다. README는 이 토큰이 N8N_API_URL 오리진에만 붙고, 웹훅 호스트가 다르면 그 호출에는 나가지 않는다고 적습니다.

인스턴스 MCP는 또 다른 비밀입니다. deriveOfficialMcpEndpoint()는 N8N_API_URL의 오리진에 /mcp-server/http를 붙입니다. 토큰 환경 변수는 N8N_MCP_ACCESS_TOKEN이고, N8N_API_KEY와 다른 값입니다. README는 n8n이 MCP를 다른 호스트(N8N_MCP_BASE_URL)에서 서빙하는 구성은 지원하지 않는다고 적습니다.

도구 면

src/mcp/tools.ts의 n8nDocumentationToolsFinal은 7개입니다. API 키 없이 이 목록이 서버가 등록하는 도구입니다. server.ts는 API가 설정되면 여기에 n8nManagementTools 21개를 더해 시작 로그의 개수로 씁니다. 7+21=28입니다. Claude Code 설정 문서의 스크린샷 설명은 "39 tools"라고 적습니다. 이 커밋의 두 배열에서 39개의 name은 세지지 않습니다.

README가 N8N_MCP_ACCESS_TOKEN을 요구한다고 적은 호출은 따로 있습니다. n8n_manage_agents, n8n_explore_node_resources(슬랙 채널이나 시트 탭처럼 자격 증명으로만 알 수 있는 값), n8n_list_catalog의 팀 프로젝트 폴백, n8n_workflow_versions의 source: 'native', 트리거 URL이 없는 워크플로를 n8n MCP로 돌리는 n8n_test_workflow의 prepare/pinned/direct, 데이터 테이블 열 변경입니다. 공개 REST만으로는 그 호출이 끝나지 않습니다.

검증은 네 겹으로 README가 적습니다. validate_node minimal은 필수 필드, full은 profile에 따른 오류·경고·제안, validate_workflow는 조립된 JSON, n8n_validate_workflow는 이미 인스턴스에 있는 id입니다. README의 예시에서는 resource/operation/text만 있는 슬랙 설정이 런타임에 실패하고, select와 channelId까지 적어야 한다고 합니다. 기본값을 비워 둔 채 넘어가는 것이 실패의 주된 자리라고 같은 절이 적습니다. 이 검증은 스키마와 정적 규칙입니다. 자격 증명이 살아 있는지, 메일이 실제로 오는지까지 증명한다고 저장소는 적지 않습니다.

설정 조각

문서 도구만 쓰는 Claude Desktop 설정은 SELF_HOSTING.md의 JSON입니다. macOS 파일은 ~/Library/Application Support/Claude/claude_desktop_config.json, Windows는 %APPDATA%\Claude\claude_desktop_config.json, Linux는 ~/.config/Claude/claude_desktop_config.json이라고 그 문서가 적습니다.

{
  "mcpServers": {
    "n8n-mcp": {
      "command": "npx",
      "args": ["n8n-mcp"],
      "env": {
        "MCP_MODE": "stdio",
        "LOG_LEVEL": "error",
        "DISABLE_CONSOLE_OUTPUT": "true"
      }
    }
  }
}

인스턴스에 만들려면 같은 문서가 두 값을 더합니다. 아래 키는 자리표시자입니다.

{
  "mcpServers": {
    "n8n-mcp": {
      "command": "npx",
      "args": ["n8n-mcp"],
      "env": {
        "MCP_MODE": "stdio",
        "LOG_LEVEL": "error",
        "DISABLE_CONSOLE_OUTPUT": "true",
        "N8N_API_URL": "https://your-n8n-instance.com",
        "N8N_API_KEY": "your-api-key"
      }
    }
  }
}

Claude Code는 CLAUDE_CODE_SETUP.md가 이렇게 적습니다.

claude mcp add n8n-mcp \
  -e MCP_MODE=stdio \
  -e LOG_LEVEL=error \
  -e DISABLE_CONSOLE_OUTPUT=true \
  -e N8N_API_URL=https://your-n8n-instance.com \
  -e N8N_API_KEY=your-api-key \
  -- npx n8n-mcp

같은 문서는 기본 범위가 --scope local이라 키가 사용자 설정에 남고, --scope project는 .mcp.json에 남는다고 적습니다. 팀을 저장소에 키와 함께 넣으라는 뜻으로 읽히면 그 문장과 어긋납니다. Cursor와 Windsurf는 README가 CURSOR_SETUP.md, WINDSURF_SETUP.md를 가리킵니다. 이 글은 그 클라이언트를 실행하지 않았습니다. "적혀 있다"와 "이 환경에서 붙었다"는 다른 문장입니다.

npx를 Claude Desktop과 Claude Code가 동시에 띄우면 npm 캐시 잠금이 겹칠 수 있다고 SELF_HOSTING.md가 적고, 클라이언트마다 다른 npm_config_cache를 주라고 합니다. 같은 기계의 n8n이 localhost이면 Docker 쪽 URL은 http://host.docker.internal:5678이고, WEBHOOK_SECURITY_MODE=moderate를 같이 줘야 루프백을 SSRF 게이트가 막지 않는다고 같은 문서가 적습니다. 기본값 strict는 루프백을 거절합니다.

호스팅 선택지는 README 기준 다섯입니다. npx n8n-mcp, ghcr.io/czlonkowski/n8n-mcp, 클론 후 npm run build, Railway 버튼, dashboard.n8n-mcp.com. 대시보드의 "Free tier: 100 tool calls/day"는 README의 문장입니다. 계정을 만들어 호출 한도를 확인하지는 않았습니다.

한 문장에서 워크플로 JSON까지

아래는 README "Workflow Process"가 적는 순서입니다. 실행 로그가 아닙니다. 사용자의 문장 예는 포스트가 든 "메일 오면 시트에 정리하고 메신저로 알림"을 개발 인스턴스에 한정한 것입니다.

사용자: 문의 메일이 오면 시트에 한 줄 추가하고 슬랙으로 알려 줘.
        프로덕션 워크플로는 수정하지 마. 초안만 개발 인스턴스에 둬.

1. tools_documentation
2. search_templates  (keyword 또는 by_task, by_nodes)
3. search_nodes      gmail / googleSheets / slack, includeExamples true
4. get_node          detail standard. 필요한 속성만이면 mode search_properties
5. validate_node     mode minimal, 이어서 mode full, profile runtime
6. 사용자에게 노드 구성 승인
7. validate_workflow 조립한 JSON
8. API 키가 있을 때만 n8n_create_workflow
9. n8n_validate_workflow  { id }

8번이 없으면 모델은 문서와 검증 결과만 가지고 있고, n8n 캔버스에는 아무것도 생기지 않습니다. 8번이 있으면 생성은 공개 API의 워크플로 생성입니다. 자격 증명 이름은 인스턴스에 이미 있는 값이어야 하고, 없는 채널 id를 모델이 지어 넣을 수 있습니다. 그걸 기존 리소스에서 찾으려면 n8n_explore_node_resources와 N8N_MCP_ACCESS_TOKEN이 README의 경로입니다.

만든 뒤의 확인은 포스트 마지막 문장과 README가 같이 가리키는 자리입니다. README의 안전 경고는 프로덕션 워크플로를 AI로 직접 고치지 말 것, 복사본을 만들 것, 개발 환경에서 시험할 것, 내보내 백업할 것, 배포 전에 검증할 것입니다. "AI results can be unpredictable"이 그 절의 문장입니다. n8n_test_workflow가 있어도 그 호출의 통과가 운영 승인인지는 저장소가 보장하지 않습니다.

읽기 전용으로 좁히려면 README가 DISABLED_TOOLS에서 생성·전체 갱신·부분 갱신·삭제·자동 수정·템플릿 배포·테스트·자격 증명·데이터 테이블 도구를 빼라고 적습니다. DISABLED_TOOL_OPERATIONS는 한 도구 안의 쓰기 연산만 막는 두 번째 스위치입니다. 여기에 "read-only n8n API key"를 겹치라고 README가 적습니다. n8n 인증 문서에서 스코프를 고르는 절차는 Enterprise이고, Enterprise가 아닌 키는 계정의 리소스와 기능 전체에 접근한다고 적습니다. 커뮤니티 에디션에 읽기 전용 키가 있다는 문장은 그 페이지에 없습니다. 키를 만든 뒤 Settings → n8n API에서 지울 수 있다는 절차는 있습니다. 무료 체험 중에는 공개 API 자체가 없다고 같은 페이지가 적습니다.

n8n이 이미 갖고 있는 MCP

n8n 문서 첫 화면은 "n8n is a fair-code licensed workflow automation tool that combines AI features with business process automation"입니다. 인스턴스 MCP는 클라이언트가 워크플로를 검색하고, MCP에 연 워크플로와 상호 작용하고, 실행·시험하고, 워크플로와 데이터 테이블을 만들고 고친다고 적습니다. 만들고 고치는 쪽은 n8n 2.13.0부터라고 같은 페이지가 적습니다. 서버 URL은 Settings → Instance-level MCP에서 복사하고 끝이 /mcp-server/http입니다. 인증은 OAuth 또는 API 키입니다. 문서가 연결 예로 적는 클라이언트에는 Claude Desktop, Claude Code, Cursor, Windsurf가 들어 있습니다.

노출은 인스턴스에서 MCP를 켠 다음 워크플로마다 "Available in MCP"를 켜는 방식입니다. search_workflows만 권한이 있는 워크플로의 미리보기를 반환하고, 본문 조회·실행·수정은 그 스위치를 켠 워크플로로 한정된다고 문서가 적습니다. execute_workflow의 기본은 게시된 버전입니다.

워크플로 한 개의 도구만 밖으로 내는 노드는 MCP Server Trigger입니다. 전송은 SSE와 streamable HTTP이고 stdio는 없다고 그 페이지가 적습니다. 반대 방향인 MCP Client Tool은 워크플로가 바깥 MCP 서버를 호출합니다. 용어집의 한 줄이 이 둘과 인스턴스 MCP를 같이 적습니다.

n8n은 코딩 에이전트용 스킬도 따로 둡니다. 인스턴스 MCP 문서의 "n8n Skills"는 n8n-io/skills를 가리키고, 13개 능력 스킬과 라우팅용 메타 스킬을 적습니다. czlonkowski의 n8n-skills는 n8n-mcp README가 선택 사항으로 가리키는 다른 저장소이고, Claude Code 설정 문서는 그 안에 7개 스킬이 있다고 적습니다. n8n-mcp 저장소 자체는 MCP 서버입니다. 스킬은 그 서버가 등록하는 tools/list 항목이 아닙니다.

비즈니스 인사이트

숫자와 회사 서술은 각 문장 옆의 출처에 붙입니다. 그 밖의 판단은 분석/의견으로 표시합니다.

같은 범주의 호스티드 자동화로 Zapier와 Make의 도움말이 자신을 설명하는 문장은 이렇습니다. Zapier 도움말(Updated November 02, 2026)은 "Zapier is the infrastructure for AI-powered automation"이라고 적고, 앱 라이브러리를 9,000+로 적습니다. Zap은 트리거와 하나 이상의 액션입니다. What is Zapier? What is a Zap? Make 도움말은 Make를 앱과 서비스를 연결해 워크플로를 자동화하는 플랫폼이라고 적고, 시나리오와 모듈이라는 말을 씁니다. What is Make? n8n 저장소 설명의 통합 수는 400+이고, 배포는 self-host 또는 cloud입니다. 9,000+와 400+와 n8n-mcp DB의 3,434는 카탈로그 정의가 달라서 이 글은 순위를 만들지 않습니다. Zapier 비교 페이지의 Make 가격·고객 수, n8n.io/pricing의 월 요금은 이 글이 인용하지 않습니다. 요금이 필요하면 n8n 문서가 가리키는 pricing을 그 시점의 페이지로 보면 됩니다.

n8n 쪽 AI 기능은 문서에 이미 있습니다. Integrate AI는 OpenAI, Anthropic, Google 같은 LLM과 도구·메모리를 워크플로에 넣는 절입니다. Use n8n MCP server는 자연어로 워크플로를 설명하면 그 인스턴스 MCP가 만들고 실행하는 경로를 적습니다. n8n-mcp가 더하는 층은 인스턴스 없이도 열리는 노드 스키마 DB, 템플릿 2,352개 검색, validate_node profile, 공개 REST로의 관리 도구입니다. 인스턴스 MCP의 리소스 조회와 에이전트는 N8N_MCP_ACCESS_TOKEN이 있을 때 n8n-mcp가 그 서버의 클라이언트가 되는 경로입니다.

라이선스는 비용을 가릅니다. n8n-mcp의 LICENSE는 MIT이고 저작권 줄은 "Copyright (c) 2024 Romuald Czlonkowski"입니다. n8n의 LICENSE.md는 Sustainable Use License 1.0입니다. 사용은 자신의 내부 업무, 비상업, 개인 용도이고, 배포는 비상업 목적의 무상일 때라는 제한이 Limitations에 있습니다. .ee. 파일은 Enterprise 라이선스라고 같은 파일이 적습니다. GitHub API의 n8n license.spdx_id는 NOASSERTION입니다. 문서 첫 화면의 단어는 fair-code입니다.

License FAQ는 커뮤니티 라이선스의 공식 이름이 Sustainable Use License이고, 셀프호스트에 적용되며 n8n Cloud는 유료 구독이라고 적습니다. 허용 예는 사업 운영, 개인 학습, 클라이언트가 워크플로를 만들거나 고치지 못하는 조건에서의 대행 구축, 구축·교육·컨설팅 요금입니다. 금지 예는 n8n을 호스팅해 클라이언트가 워크플로를 만들게 하는 것, 외부 최종 사용자가 맞춤 UI·API·MCP·사용자를 대신하는 AI 에이전트로 워크플로를 만들거나 설정하게 하는 것, 코드를 포크해 자동화 제품을 내는 것, 브랜드를 지우고 되파는 것입니다. FAQ는 판단 기준을 "누가 워크플로 로직을 정하는가"로 적고, 인터페이스가 UI인지 API인지 MCP인지 에이전트인지는 그 기준을 바꾸지 않는다고 적습니다.

공개 API는 인증 문서가 무료 체험 중에 쓸 수 없다고 적습니다. 키를 만들 때 스코프를 고르는 단계는 Enterprise입니다.

분석/의견. 이득이 가는 자리는 이미 n8n을 자기 인프라에서 돌리고, Claude Desktop·Claude Code·Cursor·Windsurf 중 하나에 노드 문서를 붙여 초안을 만든 뒤, 사람이 개발 인스턴스에서 실행을 보는 팀입니다. 컨설턴트가 자기 인스턴스에서 만들어 결과만 고객에게 넘기는 형태는 FAQ의 허용 예와 맞닿아 있습니다. 고객의 에이전트가 운영자의 n8n에 워크플로를 쓰게 하는 제품은 FAQ의 금지 예에 문장이 있습니다. 그 제품의 경로가 n8n-mcp이든 n8n 인스턴스 MCP이든, FAQ가 적은 기준은 인터페이스가 아닙니다.

손해가 읽히는 자리는 별도입니다. Zapier·Make 도움말은 각자 호스티드 자동화와 AI 기능을 이미 적습니다. n8n-mcp 별 23,199가 그 카탈로그의 사용자를 옮긴다는 수는 이 글의 출처에 없습니다. 포스트가 "강의까지 팔리는 이유"라고 적은 시장도 1차 수치를 확인하지 못했습니다. 개발자 작업이 바뀌는 지점은 캔버스에서 노드를 끄는 시간이 아니라, 도구 호출이 프로덕션 id를 만졌는지, 표현식과 자격 증명과 빈 기본값을 사람이 봤는지입니다. 별 개수는 그 확인을 대신하지 않습니다. 이 문단은 의견입니다.
