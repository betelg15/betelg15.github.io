협업 페이지와 13개 ROM

developers.openai.com/modretro의 문장은 이겁니다. ModRetro와 OpenAI가 ModRetro Chromatic의 게임 제작으로 협업하고, 그 협업은 ModRetro의 휴대 하드웨어와 OpenAI의 코딩 에이전트 Codex를 함께 둔다. “The games in this collection were built with Codex for Game Boy Color.” 브라우저에서 플레이하거나, 호환 하드웨어에 쓸 ROM을 받을 수 있다. 쇼케이스 홈의 카드 문장은 “ModRetro Chromatic Plugin for Codex / Build and play GameBoy Color games on real hardware.”입니다.

목록은 13개입니다. 각 페이지의 ROM 경로를 2026-11-09에 받아 헤더를 읽었습니다. 헤더 체크섬(0x134–0x14C를 뺀 값의 하위 8비트와 0x14D)은 13개 모두 맞았습니다. Pan Docs 기준 0x143이 $80이면 CGB와 구형 Game Boy 양쪽, $C0이면 CGB 전용입니다. 0x147의 $1B는 MBC5+RAM+BATTERY, $1E는 MBC5+RUMBLE+RAM+BATTERY입니다. 0x146(SGB 플래그)은 13개 모두 0x00이었습니다.

페이지 문장은 13개 모두를 Game Boy Color용으로 적습니다. 헤더는 그 문장과 맞습니다. 12개는 $C0이고 Arc Pocket만 $80입니다. $80도 컬러 팔레트를 쓰는 CGB 대응 ROM이고, 구형 모노크롬 기동을 헤더가 허용한다는 뜻입니다. 파일 이름만 보면 FlapGPT와 Arc Pocket이 .gb라 모노크롬 전용처럼 보이는데, FlapGPT의 플래그는 $C0입니다. 확장자와 헤더가 다릅니다.

파일 이름이 페이지 제목과 다른 경우가 있습니다. Codex Land 파일명에는 three-levels-preview-008이 들어 있습니다. 페이지는 그 파일명을 설명하지 않습니다. Seedy’s Sweet Garden 페이지의 파일은 sugar-crush-v2.gbc이고 내부 제목은 SUGARCRUSH입니다. 이 글은 그 바이트만 적고, 다른 게임과의 관계를 짓지 않습니다.

FlapGPT 페이지는 “Your browser needs Canvas and WebAssembly to play.”라고 적고, 키보드를 Move=화살표, A=X/Space, B=Z, Start=Enter, Select=M으로 적습니다. ROM 링크 문구는 “Download ROM”입니다. 같은 페이지의 “Build your game”은 새 탭으로 열리고, 컬렉션 HTML의 외부 링크는 modretro.com/00011과 Create for the Chromatic입니다. 00011은 이 글의 curl -I에서 301로 chromatic-codex-edition-quickstart-guide-By1iOlcMg에 붙고, 그 주소가 다시 301로 아래 DevDay 퀵스타트에 붙었습니다. 블로그 글은 2024-06-02, 작성자 Chris Beach의 인디 개발 모집 글이고 Codex를 설명하지 않습니다.

컬렉션은 “built with Codex”라고 적습니다. 커밋 이력, 사람 수정 비율, 플레이 시간은 그 페이지에 없습니다.

Codex에서 ROM까지

절차의 1차 자료는 ModRetro 지원 문서 Chromatic: DevDay Edition Quickstart Guide입니다. 마크다운 대안 응답의 Last updated는 2026-10-23T22:07:49.242Z(2026-10-24 07:07 KST)입니다. 그 응답의 인용 블록 첫 줄은 “ModRetro Chromatic Codex Edition”이라고 쓰고, 본문 첫 문단은 “ModRetro Chromatic: DevDay Edition”이라고 씁니다. 같은 문서가 두 이름을 같이 둡니다. 11월 9일 영상보다 앞선 갱신입니다.

문서가 적는 순서는 이렇습니다.

  1. Chromatic Firmware Updater로 펌웨어를 갱신한다.
  2. DevDay Edition에 들어 있는 활성화 코드로, 그 컴퓨터의 Chromatic Developer-Mode를 켠다. Firmware Updater에서 Ctrl-I(macOS는 Cmd-I)입니다. 문서 문장은 이 모드가 그 에디션에 포함된 카트리지에 만든 게임을 쓸 수 있게 한다는 것입니다.
  3. Codex 데스크톱을 chatgpt.com/codex에서 설치한다.
  4. Plugins 탭에서 “ModRetro Chromatic”을 찾아 설치한다.
  5. 새 채팅에서 @로 ModRetro Chromatic Plugin을 붙이고 게임을 설명한다. 문서 문장은 “Game Boy Color compatible devices and emulators”용 스킬을 제공한다는 것입니다.

준비 프롬프트는 문서에 이렇게 있습니다. 이 글은 실행하지 않았습니다.

Set up @ModRetro Chromatic Plugin so I can create games, build ROMs, and run automated playtests. Check what’s already installed and prepare the missing dependencies.

예시는 GB Studio 프로젝트입니다. 플러그인 패키지의 소스 트리는 이 글이 공개 저장소에서 확인하지 못했고, 아래는 가이드가 적어 둔 문장입니다.

Create and select a new GB Studio project at /absolute/existing-parent/MoonGarden. Make a small exploration game where a gardener collects three seeds and plants them to unlock a gate.

포함 예제 게임 이름은 “Wrecklight”입니다. 가이드는 그 리믹스를 고르고 오프닝을 버려진 연구 시설로 바꾸라고 적습니다.

에뮬레이터 단계는 Codex 안의 브라우저 프리뷰입니다.

Build my selected game and open it in the playable browser preview. Reuse that preview as we make changes.

실기 단계는 그 다음이고, 문서가 범위를 못 박습니다. “Your game will be run in an emulator and streamed to your Chromatic.” 연결된 Chromatic 위에서 ROM이 카트리지를 읽어 부팅한다는 문장이 아닙니다. 에뮬레이터 화면과 소리를 기기로 보냅니다.

Stream a two-minute live demo of my built ROM to the connected Chromatic so I can try its controls, video, and audio.

카트리지에 쓰는 단계는 별도 프롬프트입니다.

Flash my built homebrew ROM to the connected Chromatic cartridge, then guide me through manual boot, gameplay, and audio checks.

문서의 면책 요지는 이겁니다. Chromatic 스킬은 사용자가 만든 원본 ROM만 대상이다. 불법 복제, 상용 게임 에뮬레이션, 보호 우회에 쓰지 말 것. Developer mode는 자기 책임이다. 제3자 IP 권리는 사용자가 확인한다. ModRetro는 사용자 콘텐츠를 검토하거나 보증하지 않는다. 사용은 EULA를 따른다.

이 문서는 DevDay Edition의 코드와 동봉 카트리지를 전제로 플래시를 설명합니다. 스토어의 Smoke나 Cloud 같은 일반 SKU에도 같은 쓰기 경로가 열린다고 적지 않습니다. 11월 9일 영상도 그 코드가 상자에 든다고 적지 않습니다.

Game Boy Color와 GB Studio가 남기는 상한

플러그인 프롬프트가 “Game Boy hardware limits”를 검사하라고 할 때의 상한은, 이 글이 연 GB Studio 문서와 Pan Docs에 있습니다. 에이전트가 문장을 잘 따라도 이 숫자 밖으로 픽셀을 늘리지는 못합니다.

하드웨어 쪽은 Pan Docs입니다. PPU는 오브젝트를 최대 40개, 한 스캔라인에 10개까지 그립니다. 오브젝트 크기는 8×8 또는 8×16입니다. CGB 팔레트 RAM은 배경/윈도용 8개, 오브젝트용 8개이고, 팔레트마다 색 4개입니다. 색 하나는 RGB555입니다. 오브젝트 팔레트의 0번 색은 투명입니다. 배경 타일과 같은 2bpp 타일 포맷입니다.

GB Studio가 그 위에 두는 엔진 상한은 문서의 Scene Limits입니다. 장면당 액터 20, 트리거 30입니다. 화면으로 읽는 바는 A: 0/20 S: 0/96 T: 0/30 형태이고, S는 스프라이트 시트의 고유 타일 수입니다. 160×144(타일 20×18) 안에 액터가 10개를 넘으면 일부가 안 보일 수 있다고 적습니다. 이 10은 엔진이 하드웨어의 라인당 10오브젝트에 맞춰 둔 경고이고, 액터 하나가 하드웨어 오브젝트 여러 개일 수 있으므로 두 숫자를 같은 카운터로 읽으면 문서와 어긋납니다.

색 모드는 Settings에 셋입니다. Monochrome은 GB, GB Color, Super GB, Analogue Pocket. Color + Monochrome은 모노크롬 기기에서는 모노크롬으로, 컬러 기기에서는 팔레트로. Color Only는 타일 여유가 늘고 GB Color와 Analogue Pocket에서만 돕니다. Color Only가 아니면 배경 고유 8×8 타일은 장면당 192, Color Only면 384입니다. 가장 작은 배경도 160×144라 192타일 모드에서는 타일을 반복해야 한다고 배경 문서가 적습니다. 스프라이트 타일은 배경과 메모리를 나눕니다. Monochrome과 Color + Monochrome에서 배경이 128타일 이하면 스프라이트 타일 96, 배경이 192타일을 다 쓰면 64입니다. Color Only에서는 그 상한이 192과 128로 올라갑니다.

장면 팔레트는 배경 8개, 스프라이트 8개입니다. 배경 8번째 팔레트는 대화창과 메뉴에도 쓰입니다. 자동 팔레트로 고유 팔레트가 7개를 넘으면 8번이 덮여 창이 깨질 수 있다고 색 문서가 적습니다.

스프라이트 PNG가 허용하는 네 색과, 배경과의 차이는 문서에 이렇게 있습니다. #306850은 배경에는 있고 스프라이트에는 없습니다. #65ff00은 스프라이트에서 투명이고 배경에는 쓸 수 없습니다. 목록 밖 색은 가장 가까운 색으로 맞춥니다.

#071821  darkest
#306850  backgrounds only
#86c06c
#e0f8cf  lightest
