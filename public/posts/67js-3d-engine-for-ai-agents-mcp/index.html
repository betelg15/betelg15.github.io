왜 중요한가

에이전트에게 3D를 맡기는 길은 이미 둘로 갈립니다. 하나는 Blender 안에서 bpy를 실행하게 하는 길이고, 다른 하나는 three.js 코드를 쓰게 하는 길입니다. 67js는 그 사이에, 씬을 JSON 레시피로 두고 stdio MCP 도구로만 고치게 하려는 엔진입니다. 실시간 렌더러의 공개 이름은 Glaze, 오프라인 패스트레이서의 공개 이름은 Cook입니다.

개발자가 확인할 질문은 슬로건보다 다음입니다.

  • 레지스트리에 있는 패키지 이름과 npx 67js-mcp가 같은가.
  • “23개”가 현재 릴리스의 register 호출인가, 예전에 함수 정의까지 세던 숫자인가.
  • 50.9 KB와 2.6배가 어느 번들, 어느 커밋의 gzip인가.
  • “아무 에이전트나”가 프로토콜 이야기인가, 프로젝트가 돌린 클라이언트 목록인가.

기술 설명

저장소와 패키지

공개 저장소는 codepawl/67.js입니다. npm 최신 버전은 @codepawlhq/67js 0.16.0이고, license 필드는 MIT, engines.node는 >=20.19.0입니다. bin은 67js-mcp → bin/67js-mcp.mjs입니다. 이름 67js, 67js-mcp, @codepawlhq/67js-mcp, @codepawlhq/67js-render-native는 2026-11-09 레지스트리 조회에서 404였습니다.

설치 문서가 적는 줄은 별칭입니다.

npm install 67js@npm:@codepawlhq/67js
npx 67js-mcp --backend gpu --memory 192

패키지가 로컬에 없을 때의 문서 문장은 npx --package @codepawlhq/67js 67js-mcp입니다. --backend는 프리뷰 브라우저의 gpu 또는 cpu(기본 gpu)이고, --memory는 32에서 384 MiB(기본 192)입니다. 서버는 Chrome 또는 Chromium 실행 파일이 필요하고, 브라우저를 내려받지 않는다고 docs/mcp.md가 적습니다. stdio만 쓰고 HTTP MCP 리스너는 없습니다.

LICENSE 첫 줄은 “MIT License”, 저작권은 “Copyright (c) 2026 CodePawl”입니다. 이어서 번들 gl-matrix 저작권(2015–2025, Brandon Jones, Colin MacKenzie IV)과 “This license covers the authored source code. WALL-E character rights belong to Disney/Pixar.”가 있습니다. 파일은 MIT 허가 문장을 담고, GitHub API의 SPDX는 그 파일에 대해 NOASSERTION입니다.

Glaze와 Cook

src/index.js는 Renderer67과 Glaze를 함께 내보냅니다. src/renderer.js 주석은 “Glaze is the public name of the real-time renderer; Renderer67 stays for existing code.”이고, 줄은 export { Renderer67 as Glaze }입니다. 배포 build/67.module.js의 export에도 Glaze와 Renderer67이 같은 바인딩으로 있습니다.

Cook은 코어 export가 아닙니다. src/path-tracer.js는 export const Cook = renderPathTracedImage이고, 패키지 경로는 67js/addons/path-tracer입니다. path-tracer.md는 Cook을 Cook-Torrance와 “let it cook”에 대한 이름이라고 적고, 기본 backend는 cpu라고 적습니다. gpu는 WebGL2 프래그먼트 셰이더이고, 코어 번들에는 넣지 않는다고 적습니다.

같은 문서의 데모 룸(1920×1080, 64샘플, RTX 3060)은 GPU 58.15초(웜 셰이더 캐시에서 컴파일 10.3초 포함) 대 CPU 585.9초(2026-11-03)이고, 2026-11-04 재측정은 처음 보는 커널 38.7초(컴파일 7.0초), 같은 커널 다시 41.0초(컴파일 7.3초)입니다. 0.16.0 changelog 하이라이트의 “about 40 s, against 586 s”는 이 재측정과 CPU 585.9초에 대응합니다. 일반 속도 우위로 적은 문장은 아닙니다. README의 Performance claims는 같은 하드웨어의 대응 씬 비교이며, three.js에 대한 일반 속도 우위나 Blender와의 시각적 동등을 보여 주지 않는다고 적습니다.

v0.16.0 MCP의 pathTracer 스키마에는 samples, bounces, denoise, seed, maxSeconds, noiseThreshold만 있고 backend가 없습니다. path-tracer.md는 “Render jobs do not select the GPU backend yet.”이라고 적습니다. 프리뷰의 --backend gpu는 래스터 프리뷰이고, Cook의 GPU 백엔드 선택이 아닙니다. 사이트 changelog의 Unreleased에는 렌더 잡의 backend: "gpu"와 @codepawlhq/67js-render-native가 적혀 있습니다. 그 패키지는 이 글의 npm 조회에서 404였고, 태그 CHANGELOG.md는 ## 0.16.0으로 시작합니다.

에이전트가 쓰는 도구

v0.16.0 scripts/mcp-server.mjs의 register('…')는 23개입니다. 배포 번들에도 같은 23개 이름이 있습니다. main HEAD에서도 23개였습니다.

묶음 도구
조회 scene_capabilities, scene_inspect, scene_asset_catalog, scene_walkmap, mesh_inspect
만들기·고치기 scene_create, scene_create_asset, scene_apply, mesh_edit, mesh_stack
보기 scene_look, scene_review
되돌리기 scene_checkpoint, scene_restore, scene_release_checkpoint
내보내기·정리 scene_export_recipe, scene_export_glb, scene_dispose
렌더 잡 scene_render_submit, scene_render_status, scene_render_cancel, scene_render_result, scene_render_release

문서가 적는 순서는 scene_capabilities → scene_create → scene_inspect → scene_checkpoint → scene_apply(현재 expectedRevision) → scene_look입니다. 활성 씬은 하나이고, 노드는 4096, 지오메트리와 머티리얼은 각 256, 배치는 256연산, 프리뷰는 변 64–1024픽셀(기본 768×512), 렌더 잡은 최대 1920×1080, PNG 응답은 1 MiB입니다. 임의 JavaScript, 원격 URL, 호출자가 고른 출력 경로는 없다고 적습니다. 예외는 상한이 있는 GLSL postPasses(최대 4패스, 패스당 4 KB)입니다. “MCP support does not establish Blender feature parity.”도 같은 문서에 있습니다.

레시피는 format: "67js.scene", schemaVersion: 1입니다. 아래는 agent-scene.md의 예시입니다. 이 글은 실행하지 않았습니다.

import { Renderer67 } from '67js';
import { createAgentScene } from '67js/addons/agent-scene';

const scene = createAgentScene({
  format: '67js.scene',
  schemaVersion: 1,
  geometries: [{ id: 'cube', type: 'box', bevel: 0 }],
  materials: [{ id: 'blue', color: [0.1, 0.3, 0.8] }],
  nodes: [
    { id: 'mesh', geometry: 'cube', material: 'blue' },
  ],
});

const renderer = new Renderer67(canvas, scene.parts, { ground: false });
renderer.render(scene.camera);

빈 씬에 상자를 더하는 scene_apply 배치도 문서의 예입니다.

[
  { "type": "add-geometry", "geometry": { "id": "cube", "type": "box", "bevel": 0.04 } },
  { "type": "add-material", "material": { "id": "paint", "color": [0.2, 0.6, 0.8] } },
  { "type": "add-node", "node": { "id": "mesh", "geometry": "cube", "material": "paint" } }
]

클라이언트가 적을 설정은 docs/mcp.md의 예입니다. 경로는 그 문서의 Windows 예이고, 브라우저 경로는 표준 Chrome 설치에서 생략할 수 있다고 적습니다. 같은 문서는 Cursor, Gemini CLI, Claude Desktop, VS Code, OpenAI·Gemini 모델을 돌리지 않았다고 적고, 같은 command와 args로 구성하는 일은 미검증이라고 적습니다.

{
  "mcpServers": {
    "67js-scene": {
      "command": "C:/Program Files/nodejs/node.exe",
      "args": [
        "C:/projects/my-scene/node_modules/67js/bin/67js-mcp.mjs",
        "--backend", "gpu",
        "--memory", "192"
      ]
    }
  }
}

docs/mcp.md는 스키마가 JSON Schema 2020-12라고 적습니다. draft-07 검증기는 $schema와 prefixItems에서 거절하고, OpenAI strict: true는 대부분의 속성이 선택이고 additionalProperties: false가 없으며 oneOf·prefixItems·propertyNames가 문서화된 부분집합 밖이라 거절한다고 적습니다. Gemini 함수 선언은 const, oneOf, $ref, exclusiveMinimum을 쓴다고 적습니다. 기록된 에이전트 런은 Claude Code이고, 모델링 스위트는 Claude Sonnet과 Haiku만이라고 같은 문서가 적습니다.

크기 숫자가 가리키는 것

bench/size/README.md는 esbuild로 minify·트리셰이크한 gzip 바이트를 잽니다. scene:lit-box는 애드온 없는 Renderer67 상자 하나이고, entry:*는 그 엔트리가 export하는 전부입니다. three.js 열은 같은 씬을 package.json의 three 버전으로 묶은 것이고 예산이 없습니다. manifold-3d와 @dimforge/rapier3d-compat은 선택 피어라 번들에 넣지 않는다고 적습니다.

v0.16.0 bench/size/baseline.json은 threeVersion 0.187.0, three.js lit-box gzip 133,797, 67js scene:lit-box gzip 51,056입니다. 133,797/1000 = 133.8이라 홈의 “133.8 KB”와 맞습니다. 51,056/1000 = 51.1이라 홈의 “50.9 KB”와는 156바이트 차이입니다. 133,797/51,056 = 2.62입니다. budgets.json의 goals.lit-box는 50,000이고, 51,056은 그 목표를 넘습니다.

홈 문장 “50.9 KB gzip · 2.6× smaller”가 들어 있는 커밋 3d59166f74(2026-11-06, “introduce Glaze + Cook names”)의 같은 필드는 gzip 66,641, 비율 2.01이었습니다. 그 커밋에도 three.js gzip은 133,797입니다. 50.9 KB도 2.6배도 그 파일의 숫자가 아닙니다. 릴리스 커밋 84f6b073c5(2026-11-08, “Release 0.16.0”)에서 기준선이 51,056으로 바뀌어 2.6배에 가까워졌고, 홈 문장은 그대로입니다. size README의 2026-11-03 표는 또 다른 측정입니다. 67js 49,858, three.js 0.186.1의 133,652, 목표 50,000은 그때 “met”이라고 적혀 있습니다.

같은 기준선의 다른 씬은 lit-box가 아닙니다. scene:gltf-box gzip은 80,675, scene:agent-scene+lazy는 376,567, entry:path-tracer+lazy는 35,314입니다. glTF나 에이전트 레시피, Cook을 넣는 페이지의 크기를 50.9 KB로 읽으면 이 표와 어긋납니다.

에이전트 벤치가 재는 것

bench/agent-modeling/README.md의 2026-11-07 비교(이슈 #31)는 claude-sonnet-5-5, 태스크 6개, 시스템당 1회입니다. 67js MCP는 6/6, 평균 도구 호출 3.2, 평균 벽시계 24초, 평균 look 0.932입니다. three.js를 코드로 쓰게 한 쪽은 5/6, 8.8회, 359초, look 0.926입니다. 실패한 window는 닫힌 표면 검사입니다. 문서는 three.js 시간의 대부분이 헤드리스 Chrome으로 PNG를 쓰는 데 갔고, 토큰은 67js가 더 많으며(스키마를 호출마다 읽음), 태스크가 67js 스위트 기준으로 만들어졌다고 적습니다.

Blender 쪽은 “official Blender MCP server (Blender Lab, v1.0.3)”, Blender 5.1.2, 같은 여섯 태스크, 1회, Docker(x86_64를 Apple silicon에서 Rosetta)입니다. 6/6, 평균 도구 호출 3.8, 평균 벽시계 517초, look 0.926입니다. 문서는 517초를 Blender MCP 지연이 아니라 환경 비용으로 보라고 적습니다. fence만 38초였고, 나머지는 렌더 호출이 Claude Code의 300초 무응답 중단에 걸렸다고 적습니다. 서버는 가드 없는 Python을 실행하므로 벤치 기계에서 직접 돌리지 않았다고 적습니다.

비즈니스 인사이트

숫자와 문서 내용은 문장 옆에 출처를 붙입니다. 그 밖의 판단은 분석/의견입니다. CodePawl의 매출, 가격표, 기업 가치는 이 글이 연 패키지 메타데이터와 홈에서 찾지 못했습니다. npm 0.16.0의 라이선스 필드는 MIT이고, 홈과 package.json에 유료 티어는 적혀 있지 않습니다.

라이선스가 여는 범위는 엔진마다 다릅니다. three.js LICENSE는 MIT이고 저작권 표기는 2010–2026 three.js authors입니다. 2026-11-09 npm view three의 버전은 0.187.0, 라이선스는 MIT입니다. 67js 벤치가 고정한 three도 0.187.0입니다. GitHub API로 본 mrdoob/three.js는 별 117,896, SPDX MIT입니다. Babylon.js license.md는 Apache-2.0이고, 같은 조회에서 BabylonJS/Babylon.js는 별 26,309, SPDX Apache-2.0입니다. npm view babylonjs는 버전 9.35.0, 라이선스 Apache-2.0입니다. Blender 라이선스 페이지는 Blender를 GNU GPL(소스의 기본은 GPL 2 or later)로 두고, 어떤 목적으로든 사용할 수 있으며 결과물을 팔 수 있다고 적습니다. 같은 페이지는 Cycles를 Apache 2.0이라고 적습니다.

67js LICENSE는 작성 소스에 MIT를 적습니다. GitHub가 그 파일을 NOASSERTION으로 분류하는 것은 라이선스 스캐너가 SPDX를 못 고를 수 있다는 뜻이지, 파일에 MIT 문장이 없다는 뜻은 아닙니다. 분석/의견. 앱에 렌더러를 넣는 비용의 축은 three.js, Babylon.js와 같이 “라이선스 수수료가 문서에 없다”에 가깝고, GPL 앱을 고쳐 배포할 때의 소스 공개 의무와는 다릅니다. 그 판단은 각 제품이 실제로 링크하는 코드에 따라 달라지고, 이 절은 법률 자문이 아닙니다.

옆의 MCP는 코드 실행을 열어 둡니다. Blender Lab MCP 페이지는 Blender 5.1 이상, 애드온, LLM 클라이언트, MCP 서버 세 가지를 따로 설치한다고 적고, “The MCP server will execute LLM generated code in Blender without any guards”라고 경고합니다. 다운로드 링크는 v1.0.3입니다. 67js 벤치가 적은 Blender Lab v1.0.3과 같은 버전 번호입니다. 커뮤니티 저장소 ahujasid/mcp-for-blender는 API 설명이 “Not affiliated with the official Blender Foundation.”이고, 같은 조회의 별은 33,672, SPDX는 MIT입니다. 분석/의견. 67js가 받는 대가는 기능 동등이 아니라, 도구 인자 밖으로 임의 코드와 원격 URL이 나가지 않게 문서가 경계를 그은 것입니다.
