왜 파일시스템이 가중치 안에 들어가는가

포스트의 첫 문장은 순서입니다. 먼저 CPU, 그다음 GPU, 그리고 저장소가 없으면 컴퓨터가 완성되지 않는다는 문장 뒤에 qwenFS가 나옵니다. 인용된 글은 같은 작성자의 qwenGPU입니다. CPU 쪽으로 qwenGPU README가 이름을 적는 프로젝트는 다른 사람, Divyansh Agrawal의 Qwenputer입니다.

개발자에게 닿는 지점은 "모델이 파일을 기억한다"가 아닙니다. 도구 서버가 응답 토큰을 고르는 구조와, 그 선택이 포워드 패스 안의 고정 회로에서 나오는 구조는 다릅니다. qwenFS README의 문장은 플러그인도, 도구 서버도, API 뒤의 데이터베이스도 아니라는 것입니다. 파일시스템 층은 Qwen3.5-2B의 24층 앞에 붙는 8개 층이고, 그 가중치는 학습되지 않습니다. 호출은 Qwen이 원래 쓰던 도구 호출 형식이고, 응답 토큰은 그 회로가 고릅니다.

같은 계열의 앞선 파일시스템은 Qwenputer README의 "In-weight filesystem"입니다. 그쪽은 RISC-V 모델에 put append get list delete를 더하고, 이름 해시로 DeltaNet 상태의 디렉터리 슬롯을 고릅니다. 상한은 512개 파일, 약 53,000토큰입니다. qwenFS는 그 코드를 가져오지 않습니다. README Related는 qwenGPU만 링크하고, 층을 Qwen3.5의 레이어 타입에 직접 쓴다고 적습니다.

가중치는 학습 루프 없이 채워진다

qfs/circuit.py 모듈 독스트링이 층을 나눈 순서입니다. 0부터 7까지, 타입은 linear_attention 다섯 개와 full_attention 세 개입니다. linear_attention이 Qwen 카드가 Gated DeltaNet이라고 부르는 층이고, full_attention이 일반 어텐션입니다.

층 타입 하는 일 (모듈 독스트링)
P (0) DeltaNet 직전 토큰의 플래그·단어 형태를 지연 레지스터에 둔다
1 DeltaNet 경로 슬롯과 데이터 오프셋 카운터, 호출 레지스터
2 DeltaNet 경로 슬롯, 연산 레지스터, 파일 개수, 단어 플래그
3 어텐션 경로를 이전 ack의 경로와 맞춰 파일 인덱스를 찾는다
4 DeltaNet 버전 표, 경로 표, 베이스 표, 읽는 파일의 버전
5 DeltaNet ack와 호출의 소스·타깃, 쓴 텍스트의 베이스를 유지
6 어텐션 검색어와 링크 쌍을 seek 층의 행과 맞춘다
7 어텐션 읽기의 (인덱스, 버전, 오프셋)으로 저장된 토큰을 복사

embeddings()는 토큰 벡터의 지정 차원에 플래그를 심습니다. =name, =text, =target, =query, 줄바꿈, </tool_call> 같은 Qwen 도구 형식의 단일 토큰이 각 플래그 차원에서 1이 됩니다. MLP는 그 플래그 조합이 맞을 때만 relu가 1이 되도록 게이트와 업 프로젝션을 손으로 넣습니다. Delta.register는 키가 켜진 토큰에서 상태 행 하나를 쓰고, 매 토큰에서 그 행을 읽습니다. 주석은 세트 레일을 2, 8, 32, 128개 중 하나로 패딩해 헤드 노름의 스케일이 2의 거듭제곱이 되고, 읽기가 정확히 0/1 또는 ±1로 돌아온다고 적습니다.

호출 종류는 파라미터 토큰으로 갈립니다. 텍스트가 있으면 쓰기, 타깃이 있으면 링크, 쿼리가 있으면 검색입니다. 함수 이름 토큰으로 가르는 것은 unlink와 append뿐입니다. 독스트링이 그렇게 적습니다.

아래는 회로를 실행하는 코드가 아닙니다. circuit.py가 가중치에 심는 자료 배치를 줄인 스케치입니다.

# 스케치. 학습은 없다. 실제 행렬은 qfs/circuit.py의 fill()이 채운다.
# 파일 본문: copy 층(7) 어텐션 로그. 키 = (file, version, offset)
# 표: DeltaNet 행. 한 행을 덮어 버전·경로·베이스·파일 개수를 유지한다.

def on_write_token(file_i, version, offset, token_id):
    attention_log.append(key=(file_i, version, offset), value=token_id)

def on_read_token(file_i, version, offset):
    # 같은 키로 질의. 맞는 행의 값 차원이 그 토큰의 출력 코드가 된다.
    return attention_copy(query=(file_i, version, offset))

상수로 박혀 있는 상한은 NFILE = 128, 경로 슬롯 NSLOT = 8, 오프셋 카운터 NMAX = 600, 버전 비트 VB = 6, 검색어 토큰 S = 3입니다. README 한계 문장은 이 상수와 같이 읽힙니다. 파일 128개, 경로 최대 8토큰, 쓰기나 append 한 번이 약 590토큰, 파일당 쓰기와 append 63번이라 파일 하나가 약 37,000토큰입니다. 모듈 독스트링은 세그먼트가 최대 63개, 각 약 590토큰이라고 적습니다. 카운터의 정확 범위는 600토큰입니다.

파일 본문은 어텐션 로그다

쓰기나 append 하나의 본문은 copy 층 어텐션 로그에 (파일 인덱스, 버전, 오프셋)으로 남습니다. 읽기는 그 키로 질의하고, 값 프로젝션이 토큰 id 코드를 출력 차원으로 복사합니다. layer_copy 독스트링의 문장입니다. 쓰기의 텍스트 토큰만 키가 살아 있고, 텍스트를 여는 줄바꿈은 빠집니다.

한 파일은 마지막 write_file 이후의 세그먼트 사슬입니다. append는 새 버전을 하나 더합니다. 읽기는 베이스에서 시작하고, 마지막이 아닌 세그먼트의 끝에서는 </tool_response> 대신 다음 세그먼트의 읽기 ack를 냅니다. ack가 오프셋 카운터를 다시 시작합니다. 그래서 한 번의 쓰기 길이보다 긴 파일이 됩니다.

층 3의 어텐션은 경로 조회입니다. 경로의 끝 토큰이 그 파일의 인덱스를 찾고, 정확한 일치와 가까운 불일치 사이의 점수로 "not found"에 떨어집니다. 층 6(seek)은 단어마다 한 행, 링크 변화가 있을 때마다 한 행을 둡니다. 검색은 응답 토큰마다 파일 하나를, 그 파일의 현재 베이스에 대해 확인합니다. 예전 버전에만 있던 단어는 맞지 않습니다. 링크는 +1 행과 -1 행이 번갈아 쌓이고, 평균이 0보다 크면 연결된 것으로 읽습니다. 상태가 바뀌지 않는 호출은 행을 더하지 않고, Qwen에게는 같은 단어로 보이는 no-op 변형("linked" / "removed")을 냅니다.

검색이나 링크 목록이 지나치는 파일은 skip 토큰입니다. 임베딩에서 skip은 줄바꿈의 0.25배라, Qwen의 층은 그 토큰을 줄바꿈으로 읽습니다. 목록에 찍히는 마커는 "-"의 0.25배입니다. merge.py의 ALIAS = 0.25가 그 스케일입니다.

표는 Gated DeltaNet의 한 행이다

Yang, Kautz, Hatamizadeh의 Gated Delta Networks: Improving Mamba2 with Delta Rule는 arXiv:2412.06464v3, 2025-03-06입니다. NVIDIA 페이지는 ICLR 2025라고 적고, NVlabs/GatedDeltaNet의 인용 블록도 같은 학회입니다. 식 (10)은 상태 행렬을 이렇게 갱신합니다.

S_t = S_{t-1} @ (alpha_t * (I - beta_t * k_t @ k_t^T)) + beta_t * v_t @ k_t^T

alpha_t가 0에 가까우면 상태가 지워지고, 1에 가까우면 델타 규칙만 남아 맞는 키의 값만 갈아끼웁니다. 논문 서론이 그 두 끝을 그렇게 설명합니다. Qwen3.5-2B 카드의 언어 모델 배치는 이 층을 이미 씁니다. 은닉 2048, 층 24, 배치 6 × (3 × (Gated DeltaNet → FFN) → 1 × (Gated Attention → FFN)), 선형 어텐션 헤드 16, 헤드 차원 128입니다. config.json의 layer_types는 linear_attention 세 번 뒤에 full_attention이 오는 패턴이 24층 끝까지 반복됩니다. hidden_size 2048, num_hidden_layers 24, vocab_size 248320, max_position_embeddings 262144입니다.

qwenFS가 그 갱신을 레지스터로 쓰는 방식은 Qwenputer README가 RAM이라고 적은 배치와 같습니다. 게이트를 열어 두고, 키를 한 행에 고정하면 그 행만 덮입니다. circuit.py의 Delta.register는 쿼리 채널을 ONE 차원의 20으로, 베타를 30으로, 감쇠 입력을 -100으로 두어 그 행이 매 토큰 유지되게 합니다. 오프셋은 다른 머리입니다. 모듈 독스트링은 앵커 이후 alpha = 2^(-1/16)로 줄어드는 카운터를, 헤드 노름의 eps 구간에서 읽어 600토큰까지 정확히 디코드한다고 적습니다. 코드의 감쇠 상수는 Y = -3.125입니다. 이 글은 그 로짓이 Qwen 구현에서 어떤 alpha로 풀리는지 다시 계산하지 않았습니다.

현재 main에서 DeltaNet이 잡는 표는 버전, 베이스, 경로, 파일 개수, 호출 상태입니다. 링크 행은 seek 어텐션에 있습니다. 그 이동은 커밋 6e3eaee47bf3bc687a084f8d5a8737eb9072a8a6(2026-11-04T18:41:48Z, "128 files: links and search on a seek layer")입니다. 포스트 시각의 트리 164f690 README는 링크를 DeltaNet 상태의 (source, target) 행으로 적고, 파일 상한을 32로 적습니다.

정확도를 고정하는 다른 장치는 밸러스트입니다. 토큰마다 4차원에 8192를 넣고, 주석은 sqrt(4 * 8192^2 / 4096) = 256이 되어 FS 층 노름이 상수 스케일이 된다고 적습니다. 꺼진 키는 0 근처가 아니라 0보다 훨씬 아래에 둡니다. 주석이 이유를 적습니다. DeltaNet 키의 l2 노름이 작은 값을 다시 1로 키우기 때문입니다.

병합 뒤에 남는 것, 그리고 디스크

qfs.merge는 잔차를 2048에서 4096으로 넓히고, Qwen 행렬의 빈칸을 0으로 채우고, 디코더와 최종 노름 게인에 sqrt(2048/4096)을 곱합니다. FS 층이 앞쪽 8개, Qwen 층이 뒤쪽 24개입니다. FS 토큰은 어휘 뒤에 붙습니다. 출구 MLP는 FS 차원을 지우고, id 차원에만 EPS = 1/64 크기의 출력 코드를 남깁니다. 최종 노름이 그 코드를 키워, 강제 토큰이 Qwen의 로짓보다 앞에 섭니다. 코드가 0인 위치에서는 Qwen 로짓이 그대로입니다. README는 상위 1 예측이 확인한 139곳에서 같고, KL이 약 2.5e-3이라고 적습니다. 원인은 bf16으로 게인을 반올림한 것이라고 같은 문장이 적습니다.

merge.py 맨 위 독스트링은 아직 "2048 to 3072"와 sqrt(2048/3072)라고 적습니다. 같은 파일의 WIDE는 sqrt(2048 / F.H)이고 circuit.py의 H는 4096입니다. README도 4096입니다. 독스트링과 상수가 어긋나 있습니다.

디스크는 모델 가중치 밖의 이미지입니다. disk.py는 경로, 세그먼트 길이, 토큰 id 3바이트, 링크 쌍을 디렉터리에 씁니다. README는 저장 토큰당 약 3.3–3.8바이트라고 적습니다. 새 세션은 표를 마운트하고, 모델이 그 세그먼트의 읽기 ack를 내는 순간에만 본문을 페이지인합니다. 페이지인은 토큰 id를 그 층의 k_proj, k_norm, v_proj로 다시 넣어 copy 행을 만듭니다. 호스트가 본문을 생성하지는 않고, 행을 다시 심습니다.

README "What runs where"가 위치를 나눕니다.

  • 가중치: 호출 파싱, 조회, 표 갱신, 강제 토큰, 읽기로 복사되는 토큰. 응답이 무슨 말을 할지는 모델 밖이 정하지 않는다.
  • qfs/chat.py: 토큰을 디코드하고 <|im_end|>에서 멈춘다. 온도 0.7. 그리디에서는 2B 모델이 도구 호출을 반복하는 경향이 있다. 강제 토큰은 로짓이 수백 앞서 샘플링이 바꾸지 못한다.
  • qfs/disk.py: 읽기 ack가 나오면 런타임이 그 파일의 바이트를 올린다. README는 디스크 컨트롤러에 비유한다.
  • qfs/monitor.py: 패널이 DeltaNet 상태에서 파일시스템을 읽어 그린다. 패널은 자기 사본을 두지 않는다.

코드의 기본 온도도 0.7입니다. bridge.py의 Session 기본 temp와 chat.py의 --temp가 그렇습니다. Chat의 기본 top_p는 0.9입니다. README 본문은 top-p를 적지 않습니다.
