왜 이 라이브러리가 인디 이펙트에 닿는가

포스트의 본문은 인디 게임을 만드는 사람에게 244가지 픽셀 이펙트가 오픈소스로 나왔고, PNG 에셋 대신 짧은 자바스크립트가 실시간으로 그리며, 팔레트는 코드 한 줄이고, Claude Code용 스킬이 새 이펙트를 만든다는 문장입니다.

저장소는 있습니다. GitHub 전체 이름은 patch-gg/pixelfx, 설명 문장은 "244 pixel art effects, every one a small piece of code. Plus a Claude Code skill to make your own.", SPDX는 MIT, 기본 브랜치는 main, 생성 시각은 2026-10-30T06:43:25Z, pushed_at은 2026-10-31T08:44:14Z, 아카이브 상태는 아닙니다. 주 언어 필드는 JavaScript입니다. homepage는 patch-gg.github.io/pixelfx입니다. 조직 patch-gg의 API blog는 https://patch.gg/이고, 그 페이지를 2026-11-05에 열었을 때 보이는 문장은 "Coming soon."과 "Patch is almost ready."입니다. 직원 수나 매출은 그 페이지에 없습니다. package.json 버전은 0.3.0이고, 그 문자열은 커밋 메시지 "pixelfx 0.3.0: give the effects a body that performs them"에도 있습니다. 릴리스 목록과 태그 목록은 이 날 API에서 빈 배열이었습니다. npm 레지스트리 GET /pixelfx는 Date: Thu, 05 Nov 2026 03:19:50 GMT에 HTTP 404, 본문 {"error":"Not found"}였습니다.

개발자에게 닿는 지점은 "고퀄리티 이펙트 244개"라는 형용사보다, 프레임을 그림 파일로 들고 있지 않다는 점입니다. README가 브라우저 쪽으로 적는 이름은 canvas, Phaser, PixiJS, Kaplay, three.js이고, 그 경로는 코드를 직접 부릅니다. Godot, Unity, GameMaker, Defold, LÖVE, Bevy 쪽으로 적는 경로는 node tools/render.mjs ice/frost-nova --sheet가 만드는 투명 PNG와 Aseprite 스타일 JSON입니다.

이펙트 하나는 파일이고, 그림은 두 버퍼다

README의 개수 마커는 <!-- count -->244<!-- /count -->이고, docs/CATALOG.md 첫 문장은 "244 effects in 21 categories"입니다. 카탈로그 표의 범주 합도 244입니다. moves 12, fire 12, explosions 12, water 12, ice 10, lightning 11, sci-fi 12, melee 12, impacts 11, projectiles 13, spawn & death 10, arcane 12, holy 10, shadow 12, status 13, nature 13, weather 12, ui 12, pickups 11, transitions 10, critters 12. src/fx/categories.js의 배열도 이 21개입니다.

src/fx 아래 .js 파일은 266개입니다. 그중 export const meta가 있는 파일은 244개입니다. 나머지 22개는 범주 20곳의 _lib.js 20개, 생성 파일 src/fx/index.js, 범주 목록 src/fx/categories.js입니다. moves에는 _lib.js가 없습니다. src/fx/fire/_lib.js 첫 주석은 앞의 _가 도구가 그 파일을 이펙트로 세지 않게 한다고 적고, 불꽃 혀·연기 레시피가 Sprite Fusion의 오픈소스 fire에서 왔으며 MIT, Copyright (c) 2026 Hugo Duprez라고 적습니다.

커밋 메시지는 "244 effects, 73 of them acted."입니다. export const act가 있는 파일은 73개이고, 그 가운데 moves 12개는 전부 act를 가집니다. 나머지 61개가 README가 "61 effects with a character, and the 12 moves"라고 적는 61과 같습니다. .claude-plugin/plugin.json의 description은 "ready-made effects in 20 categories"라고 적습니다. 카탈로그와 categories.js의 범주는 21개입니다.

그리는 방식은 두 가지이고, README "how it works"와 docs/AUTHORING.md가 이름을 붙입니다.

  • Pure. draw(p, t, o)를 내보냅니다. 시각 t만으로 그 프레임이 정해져서 루프가 이음새 없이 이어진다고 README가 적습니다. 이 커밋에서 export function draw 또는 export const draw가 있고 create export는 없는 meta 파일은 112개입니다.
  • Simulated. create(o)를 내보냅니다. 파티클과 파편, 빛을 상태로 두고 스텝합니다. meta 파일 중 create export만 있는 것은 132개입니다. 둘 다 내보내거나 둘 다 없는 meta 파일은 0개입니다.

라이브 인스턴스는 src/core/fx.js의 createFx입니다. 시뮬레이션의 update는 호출자의 dt를 120Hz 이하로 나눕니다. 주석의 이유는 프레임 레이트가 달라도 같게 보이게 한다는 것입니다.

update(dt) {
  t += dt;
  if (!impl.update) return;
  // simulations step at 120 Hz or finer whatever the caller's frame rate, so they look the same everywhere
  const n = Math.max(1, Math.ceil(dt * 120 - 1e-9));
  for (let i = 0; i < n; i++) impl.update(dt / n, opts);
},

버퍼는 두 개입니다. createFrame이 만드는 객체는 { w, h, ox, oy, color, light }이고, color와 light는 Uint32Array입니다. 주석은 Sprite Fusion VFX 프레임과 같은 모양이라고 적습니다. color는 불투명·디더·반투명 픽셀이고, light는 위에 더하는 글로우입니다. composite는 그 둘을 RGBA 바이트로 섞습니다. bg가 null이면 투명입니다.

갤러리 gallery/app.js는 canvas.getContext("2d"), createImageData, putImageData입니다. src/ 안에서 WebGL이나 getContext 문자열은 검색되지 않았습니다. WebGL이라는 단어가 있는 곳은 스킬 문서입니다. skills/pixelfx/SKILL.md는 Canvas나 WebGL 게임에서 코드를 직접 쓰고, WebGL 엔진이면 합성된 RGBA를 텍스처로 올리라고 적습니다. 생성기가 셰이더를 컴파일한다는 문장은 그 파일에 없습니다.

시드는 이펙트 옵션입니다. AUTHORING.md는 Math.random()과 Date를 쓰지 말라고 적습니다. 이 커밋의 src/fx에서 Math.random 문자열은 검색되지 않았습니다.

팔레트는 이펙트 파일을 고치지 않는 옵션입니다. ice/frost-nova.js의 meta는 어두운 색에서 밝은 색으로 가는 hex 배열을 기본값으로 가집니다.

resolveOptions는 호출자가 넘긴 램프의 길이가 기본값과 다르면 fit으로 기본 길이에 다시 샘플합니다. 그래서 이펙트 안의 C[6] 같은 인덱스가 호출자의 배열 길이와 어긋나지 않습니다. README의 파란 불꽃 예는 렌더 도구의 --opts입니다.

node tools/render.mjs fire/torch --gif --opts '{"palette": ["#102","#215","#43a","#8cf","#cff","#fff"]}'

같은 README는 힐이 분홍으로 빛날 수 있다고 적습니다. "1초"라는 측정은 README, AUTHORING, fx.js에 없습니다.

줄 수는 이 커밋의 meta 파일 244개를 wc -l과 같이 개행 수로 센 값입니다. 최솟값은 moves/pistol-shots.js 38줄입니다. 그 파일은 자기 픽셀 루프가 없고 chain()으로 muzzle-pistol, bullet-tracer, hit-spark를 시각에 맞춰 부릅니다. 정렬했을 때 122번째와 123번째가 둘 다 133줄(arcane/blink-out.js, melee/thrust.js)이라 중앙값은 133줄입니다. 평균은 147.4줄, 합은 35,965줄, 최댓값은 spawn/summon-rise.js 412줄입니다. 카탈로그가 예로 드는 ice/frost-nova.js는 215줄입니다. README의 "small piece of code"는 저장소의 표현이고, 포스트의 "단 몇 줄"과 같은 문장은 아닙니다.

게임 루프에 넣는 호출

README의 브라우저 예는 의존성 없이 pixelfx와 pixelfx/fx/ice/frost-nova를 import합니다. package.json의 exports는 "."가 ./src/core/index.js, "./fx/*"가 ./src/fx/*.js입니다. 설치 줄은 npm i github:patch-gg/pixelfx이거나, src/core와 쓸 이펙트 파일을 복사하는 것입니다. engines.node는 >=18입니다. dependencies 키는 없고, devDependencies는 esbuild ^0.25.10 하나입니다.

import { createFrame, clearFrame, createFx, composite } from "pixelfx";
import * as frostNova from "pixelfx/fx/ice/frost-nova";

const frame = createFrame(320, 180);                   // your game's pixel resolution
const img = new ImageData(320, 180);
const fx = createFx(frostNova, { x: 160, y: 140 });   // also: flip, angle, seed, palette, light...

function tick(dt) {
  fx.update(dt);
  clearFrame(frame);
  fx.draw(frame, "back");                              // behind characters
  drawCharacters();
  fx.draw(frame, "front");
  composite(frame, img.data, backgroundColor);         // color, then light added on top
  ctx.putImageData(img, 0, 0);                         // scale up with image-rendering: pixelated
}

createFx가 돌려주는 객체의 메서드는 update(dt), draw(frame, layer), stop(), done()입니다. draw의 "back"은 캐릭터 뒤, "front"는 앞이고, layer를 생략하면 둘 다입니다. stop() 이후 페이드 상수는 FADE = 0.3초입니다. done()은 그 페이드가 끝났거나, 루프가 아닌 이펙트가 duration에 도달했을 때 참입니다.

캐릭터가 있는 이펙트는 createAct로 몸과 타격을 같이 재생합니다. README가 예로 든 melee/sword-slash의 act 데이터는 준비 자세, 스냅, 0.14초 히트스톱을 가집니다.

export const act = {
  target: { x: 58 },
  poses: [
    [-0.55, GUARD],
    [-0.3, WIND_UP],
    [0, CUT, "snap"],
    [0.06, FOLLOW_THROUGH, "snap"],
    [0.86, GUARD],
  ],
  hits: [{ t: 0.06, stop: 0.14, shake: 0.18, amp: 2, push: 2.8, straw: 18 }],
};

src/core/rig.js는 고정 길이 뼈의 3D 골격을 픽셀로 그린다고 README가 적고, 포즈는 12fps 스텝, 파티클은 풀 레이트입니다. 스톡 캐릭터 크기는 AUTHORING.md의 24×38 px(actor: 2)입니다. 이 글은 그 골격을 실행해 보지 않았습니다.

다른 엔진용 시트는 tools/render.mjs입니다. --sheet는 투명 PNG와 JSON을 쓰고, README는 그 JSON을 Aseprite 스타일(프레임 사각형, duration, meta.pixelfx의 fps·loop·columns·pivot)이라고 적습니다. Phaser의 atlas 로더와 Godot·Unity의 Aseprite 임포터가 읽는다고 같은 문단이 적습니다. node tools/sheets.mjs는 라이브러리 전체를 sheets/로 내보냅니다. 저장소에 미리 구워 둔 이펙트 PNG는 없습니다. 이미지 파일은 docs/readme/montage.gif와 docs/readme/acts.gif 두 개입니다.

새 이펙트의 공식 루프는 node tools/new.mjs, node tools/render.mjs(콘택트 시트), node tools/check.mjs(새어 나감, 이음새, 시드 없는 난수, 느린 프레임)입니다. Claude Code 스킬은 skills/pixelfx이고, README의 설치는 /plugin marketplace add patch-gg/pixelfx 다음 /plugin install pixelfx@pixelfx이거나 그 디렉터리를 ~/.claude/skills/에 복사하는 것입니다. 스킬 본문이 방법을 돌리는 문장은 draft, render, look, refine입니다. 한 번의 프롬프트가 끝난다는 초 단위 측정은 그 파일에 없습니다.

라이선스

LICENSE는 MIT입니다. 저작권 줄은 Copyright (c) 2026 Patch와 Copyright (c) 2026 Hugo Duprez입니다. README는 코드와 이펙트를 상업 이용을 포함해 뭐든 쓸 수 있다고 적습니다. 조건은 저작권 고지와 허가 고지를 사본에 남기는 것입니다.

비즈니스 인사이트

숫자와 문서 사실은 위에 붙입니다. 에셋 스토어 판매량과 점유율은 이 글이 측정하지 않았습니다.

비용으로 문서가 적는 것은 라이선스 가격이 아닙니다.
