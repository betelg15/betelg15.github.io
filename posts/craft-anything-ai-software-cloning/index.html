왜 중요한가

“다른 앱을 보여 주면 AI가 비슷한 걸 만들어 준다”는 말은 2026년 에이전트 도구의 단골 약속입니다. 실제로 갈리는 지점은 세 곳입니다.

  1. 스크린샷을 코드로 옮기는 도구 — 보이는 화면을 HTML로 바꾸는 쪽입니다. 바이너리·게임 루프·“만든 결과가 원본과 얼마나 같은지”까지 닫힌 고리로 돌리지는 않습니다.
  2. 리버싱 도구 — Ghidra·JADX·apktool처럼 파일을 읽는 쪽입니다. 읽은 결과를 새 프로젝트로 만들고, 다시 화면과 맞춰 고치는 제품은 따로입니다.
  3. 코딩 에이전트 — Claude Code·Codex는 글을 코드로 바꿉니다. 원본을 어떤 증거로 보고, 어디까지 베끼면 안 되는지는 보통 사용자가 프롬프트로 정합니다.

Craft Anything은 그 셋을 한 저장소에 묶습니다. README 첫 문장은 이겁니다.

See how any website, app or game works, then have AI build your own version; an open-source, clean-room engine in pure Rust.

개발자 입장에서 확인할 질문은 슬로건보다 다음입니다.

  • 루프는 정말 “분석 → 생성 → 화면 비교 → 수정”인가, 화면 비교가 전부인가?
  • Windows 설치 파일과 한국어 문서가 있는가, 그 한국어는 영어와 같은 커밋인가?
  • Codex는 “초기 알파”이고 Claude Code가 더 검증됐다는 말이 문서와 맞는가?
  • “rea에 이어”는 이 저장소가 밝히는 계보인가?
  • 구글 플레이 상위 앱 클론은 기능으로 적혀 있는가?

네 단계와 실제로 비교하는 법

README의 순서는 Study → Build → Check → Ready이고, 상태 문서는 여기에 Refine을 붙입니다. 기본 설정(crates/engine/src/settings.rs의 BuildSettings::default)은 이렇습니다.

  • 웹 비교 너비 1440, 768, 390 px (비어 있으면 이 기본값)
  • 시작 페이지 외 추가 페이지 최대 4
  • 앱에서의 추가 다듬기 라운드 6, 닮음 90%에서 중단
  • CLI --rounds 기본값은 2 (apps/craft-anything-cli/src/rebuild_cmd.rs, default_value_t = 2)

웹 검사 WebVisualCheck는 만든 사이트를 루프백에 띄운 뒤, 원본과 같은 너비로 다시 찍습니다. 점수는 레이아웃(16px 타일 평균색이 맞는 비율)과 디테일(밝기의 SSIM)의 평균입니다. website.rs가 도구 결과(0–1)를 퍼센트로 바꾸는 식은 (layout + detail) * 50.0입니다. 텍스트·DOM 구조·색·글꼴·간격·가로 스크롤·콘솔 오류·메뉴는 노트와 claim으로 붙고, 점수 자체는 바꾸지 않습니다. claim이 하나라도 실패하거나 비교하지 못한 항목이 있으면 90%여도 통과가 아닙니다 (docs/STATUS.md의 Rebuild workflow 행).

흔들리는 부분(캐러셀, 영상, 애니메이션)은 비교에서 뺍니다. website_tools.rs는 같은 페이지를 간격을 두고 세 번 찍어 noise-<width>.png 마스크를 만들고, web_pixels_compare의 ignore로 넘깁니다.

// crates/engine/src/tools/website_tools.rs (요지)
// 같은 페이지를 두 번 더 찍어, 스스로 바뀐 칸만 마스크로 남긴다.
let second = photograph(client)?;
settle(client, 1300)?;
let third = photograph(client)?;
let mask = NoiseMask::between(&a, &b, 24).union(&NoiseMask::between(&a, &c, 24));

게임은 화면만으로 Ready가 되지 않습니다. self_test.rs의 계약은 빌드된 게임이 --self-test <file.json>으로 move / act / hud를 자기 상태에서 재고, 세 단계가 모두 통과해야 한다는 것입니다. 앱·게임의 창 스크린샷 닮음은 기본값에서 picture_good_enough가 비어 있어 보고만 하고, 통과선을 그리지 않습니다.

프로젝트 폴더는 Documents/Craft Anything 아래 craft.json, capture/, app/, checks/, investigation.cany/, inbox/입니다.

Clean room과 Deep

기본은 Clean room입니다. 원본의 코드·파일·페이지 소스를 읽지 않고, 방문자가 보는 화면(스크린샷, 보이는 글, 측정한 레이아웃·색·글꼴·간격, 연 메뉴)과, 허용하면 창 사진만 씁니다. 안을 보는 도구는 거절되고 Deep를 켜라고 안내합니다.

Deep는 내장 디코더·디스어셈블러·디컴파일러와, 설치돼 있으면 Ghidra를 씁니다. 웹은 JavaScript를 읽고 시작 페이지를 지켜봅니다. README는 이 구분이 운영체제 샌드박스가 아니라고 못 박습니다. 코딩 에이전트는 사용자 권한으로 돌고, Claude Code의 읽기를 막는 방식은 에이전트마다 다릅니다 (docs/claude-code.md).

docs/tools.md는 cargo xtask tools가 생성한 목록이고, 이 커밋 헤더는 엔진 도구 302개입니다. 글머리표도 302개입니다. 영어 README는 “320 tools (300 in the engine)”, 한국어 README는 “314개 도구(엔진에 298개)”라고 적습니다. 같은 커밋에서 세 문서의 도구 수가 서로 다릅니다. 생성된 tools.md를 엔진 도구의 기준으로 보는 편이 맞습니다. AI·setup 계층(rebuild_*, ai_*, setup_*)은 그 위에 더해지고, 영어 README의 320은 그 합을 가리키는 문장입니다. 302와 300이 이미 어긋나므로 320을 정확한 합으로 쓰지는 않겠습니다.

Android 정적 도구(패키지, 클래스, 리소스, 컴포넌트, Flutter/Dart, JEB)와 adb 도구(설치 앱 목록, 스크린샷, 기기에서 앱 복사 등)는 docs/tools.md에 있습니다. docs/tool-status.md 요약표는 Android 기기(adb)를 검증 2, 미검증 23, 비고 “no device attached”로 둡니다. 이 표가 “플레이 스토어 상위 차트를 클론한다”는 뜻은 아닙니다.

웹 빌드는 파일을 브라우저에서 식별하는 WebAssembly 뷰어입니다 (packaging/web). 데스크톱의 Study→Build 루프 전체가 브라우저 안에서 도는 형태는 README가 말하지 않습니다. Flatpak은 샌드박스라 이 컴퓨터의 브라우저를 띄우지 못해, 웹사이트 조사에는 다른 패키지를 쓰라고 합니다.

어떤 에이전트로 만드는가

빌드에는 이 컴퓨터에 로그인된 코딩 에이전트가 필요합니다. 영어 README가 순서를 이렇게 적습니다.

  • Claude Code를 먼저 지원합니다. 설치된 claude를 고치지 않고 실행하고, 계정은 Craft Anything이 보지 않습니다. docs/STATUS.md는 headless로 Opus 5.5(설정이 없으면 high effort)를 돌리고, 2026-11-02 Mac에서 Claude Code 2.1.316 라이브 런을 적습니다.
  • Codex 어댑터는 있습니다. README 원문: “A Codex adapter exists but hasn't been verified on a real install yet.” docs/codex.md는 codex exec가 비대화형이라 rebuild_start 승인이 필요하고, 스타트업 도구 발견은 Codex CLI 0.166.0·루프백 모델로 봤으며 “No real-account build was run.” 이라고 끝냅니다. docs/ROADMAP.md의 “run codex exec on a real install” 항목은 아직 체크돼 있지 않습니다.
  • GitHub Copilot, Grok Build, ACP 에이전트(Gemini CLI, Qwen Code, opencode, goose, Hermes, Maki)가 영어 README에 있습니다. 그중 라이브로 돌렸다고 한 것은 Maki뿐입니다(README). STATUS는 그 뒤로 Copilot·Grok·Aider·DeepSeek Harness의 라이브 기록을 더 적습니다. README Status의 “다른 코딩 에이전트는 구현만 되고 라이브는 아직”은 STATUS보다 거친 문장입니다.
  • 질문·분석용 API로는 Anthropic, OpenAI, OpenRouter, xAI(Grok, XAI_API_KEY), 로컬 OpenAI 호환 서버가 Settings → AI에 있습니다. 이 키만으로 빌드 루프가 라이브 검증됐다는 뜻은 README “Partly there”가 부정합니다.

프로젝트 전체 배지는 early alpha입니다. “초기 알파”는 Codex만의 딱지가 아니라 제품 상태입니다. Codex는 그 안에서도 “실제 설치에서 빌드를 확인하지 않음”으로 한 단계 더 좁습니다.

실행

릴리스 설치 파일이 있으면 Rust 툴체인은 필요 없습니다. 소스는 README 기준입니다.

git clone https://github.com/storytold/craft-anything && cd craft-anything
cargo run --release -p craft-anything
cargo install --path apps/craft-anything-cli
craft-anything-cli doctor
craft-anything-cli rebuild https://example.com "Recreate this website"
craft-anything-cli rebuild - "A snake game in Rust" --rounds 1

Debian/Ubuntu 데스크톱 빌드는 libxkbcommon-dev 등 X11/Wayland/GTK 개발 패키지가 필요하다고 README가 적습니다. 의존성 설치 스크립트(npm 등)는 이 컴퓨터에서 코드를 실행할 수 있어, 처음 보는 종류의 명령은 묻고, npm을 “항상 허용”하면 이후 npm은 묻지 않습니다.

검사에 AI는 필요 없습니다. craft-anything-cli mcp로 같은 도구를 MCP 클라이언트에 넘길 수 있습니다.

한국어가 가리키는 것

두 층이 있습니다.

  1. README.ko.md — 루트에 있고 영어 README 언어 막대에서 링크됩니다. 334줄입니다(영어 README는 427줄).
  2. 앱 UI — docs/localization.md가 Settings → General → Language의 한국어(ko) 를 적고, crates/ui-egui/src/i18n/ko.tsv가 있습니다. 용어는 클린룸 / 심층, 분석 / 만들기 / 검사 / 완성, 문장은 합니다체라고 그 문서가 적습니다.

같은 커밋에서 한국어 README의 “현재 상태”는 영어와 다릅니다.

  • 영어: 공개 릴리스(Windows·macOS·Linux·FreeBSD 설치 파일)가 Releases에 있고, 다음은 managed tier.
  • 한국어: “다음: 첫 공개 릴리스(…설치 프로그램과 브라우저 뷰어는 CI에 준비되어 있음)”.

한국어 파일의 다운로드 절은 바로 아래에서 최신 릴리스의 Windows MSI를 안내합니다. 상태 절과 다운로드 절이 한 파일 안에서 어긋납니다. AI 절도 영어보다 짧아서, Copilot·Grok·ACP·Aider·DeepSeek Harness가 빠지고 Codex만 “실제 설치 환경에서는 아직 검증되지 않았습니다”로 남습니다. 한국어 문서가 있다는 사실과, 그 문서가 이 커밋의 영어 본문과 같다는 사실은 다릅니다.

비즈니스 인사이트

숫자·제품 서술은 문장 옆 출처에 붙입니다. 그 밖의 판단은 분석/의견으로 표시합니다. 매출·DAU·기업 가치는 적지 않습니다.

같은 유행의 이웃. morluto/rea는 2026-04-14에 만들어진 TypeScript 저장소입니다(MIT, 설명 “Reverse engineer anything with agents…”, 홈페이지 rea.tools). 2026-11-08 08:14 KST API는 별 440,915, 포크 109,098입니다. Craft Anything보다 약 6개월 반 앞섭니다. 공개 README는 에이전트가 MCP로 바이너리·Electron·.NET·웹을 조사하고 증거를 받아 구현을 쓰게 하는 도구 묶음으로 자신을 설명합니다. Craft Anything README·NOTICE·이 커밋 검색에는 rea라는 이름이 없습니다. abi/screenshot-to-code는 2023-11-14 생성, MIT, 같은 시각 별 81,078, 설명은 스크린샷을 HTML/Tailwind/React/Vue로 바꾸는 도구입니다. 부모 커뮤니티 저장소 storytold/artcraft는 Apache-2.0, 별 39,539, 설명은 아티스트용 크래프팅 엔진입니다. Craft Anything README는 PhotoCraft·VectorCraft 등 “Craft App Suite”의 한 칸으로 자신을 놓고, 사이트는 getartcraft.com입니다.

분석/의견. 화면을 코드로 바꾸는 도구와, 파일을 읽는 리버서와, 구독제 코딩 에이전트가 이미 따로 있습니다. Craft Anything이 더하는 것은 그 사이를 검사 점수로 닫는 데스크톱 루프입니다. REA 별 44만은 관심의 크기이지, Craft Anything이 그 코드의 후속판이라는 증거가 아닙니다. screenshot-to-code는 웹 화면의 한 장에 강하고, Craft Anything의 웹 검사는 세 너비·노이즈 마스크·claim·최대 6라운드까지 갑니다. 게임 자기테스트와 Deep 모드의 Ghidra는 그 저장소의 범위 밖입니다.

누가 이득을 보나. (1) 자기 사이트·자기 바이너리를 증거와 함께 다시 짜 보고 싶은 개발자 — Clean room은 바깥만, Deep는 소유·허락이 있을 때. (2) ArtCraft가 말하는 제작자 커뮤니티 — README는 페인팅·영상·디자인 쪽 디스코드(discord.gg/artcraft)를 본진으로 둡니다.
